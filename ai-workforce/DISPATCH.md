# The Dispatch — 20 agents, 4 departments

Added per the owner's direct instruction: a third division, sitting
physically between the original 40's building and Edgex Clips' 50-agent
wing (see `office/index.html`), with one job that splits into two
halves:

1. **Never let a real, idle agent sit idle.** Across all 90 other
   agents, the instant one goes idle, Dispatch finds it and assigns the
   correct next task — not just any open item, the right one for that
   agent's actual role.
2. **The instant Dispatch itself has nothing to dispatch, it hunts new
   money-making opportunities and organizes the team to build them.**
   Standing idle time for this division specifically gets redirected
   into growth, not busywork.

Read this before any of this division's agent files — every one of
them points back here the same way the original 40 point back to
`BRAND.md` and Edgex Clips points back to `VIDEO-DESK.md`.

## This division doesn't own a third approval gate

Dispatch assigns internal work and generates ideas — that's free to do,
same as any other internal research/ops work in this studio. It does
**not** get its own bypass around the rules that already exist:

- Anything that becomes client-facing or goes to the public still
  clears the relevant division's own gate — **Last Touch** for the
  original 40's work, **Video Last Touch** for Edgex Clips' work —
  before Chief of Staff ever sees it. Dispatch doesn't invent a third
  gate; **Launch Readiness Agent**'s whole job is routing a venture's
  output to whichever existing gate actually applies.
- Anything that spends real money still goes through the weekly budget
  process, never through Dispatch or Chief of Staff directly — same
  exception that holds everywhere else in this studio.
- A new opportunity gets logged to the `opportunities` collection (see
  `OPERATIONS.md`) the same way it always has — Dispatch's Opportunity
  Discovery department is a dedicated, always-on version of that same
  mechanism, not a replacement for it.

## Task Dispatch (5 agents) — the zero-idle engine

This is `OPERATIONS.md`'s zero-idle policy and the hourly autonomous
shift, given a dedicated standing team instead of leaning on one
Routine firing once an hour. Idle Watch Agent finds the idle agent,
Task Matcher Agent picks the right task for that specific role,
Priority Triage Agent breaks ties when more than one task wants the
same idle agent, Handoff Verification Agent confirms the assignment
actually lands (not silently dropped), and Dispatch Log Agent keeps
every assignment on the record — who, what, when, why — so the whole
loop is auditable, not a black box no one can check.

## Capacity & Queue (5 agents) — makes sure Dispatch has a real backlog

Dispatch can only assign the correct next task if a real, ready backlog
actually exists. Backlog Curator Agent maintains that queue per
department; Capacity Tracker Agent tracks real load across all 90
agents; Bottleneck Spotter Agent flags departments that are
structurally overloaded or structurally idle (a pattern, not a one-off
moment); Cross-Division Load Balancer looks for real, sensible ways to
shift help between the original 40 and Edgex Clips when one is
swamped and the other has room — without ignoring that each division's
work still needs that division's own expertise and still clears that
division's own Last Touch; Queue Health Reporter tells Chief of Staff
honestly whether the zero-idle policy is actually holding, not an
optimistic gloss.

## Opportunity Discovery (5 agents) — hunts new money the instant it's free

Standing Opportunity Scout is the always-on version of the studio's
original Opportunity Scout — instead of one agent picking this up when
someone remembers to ask, this department exists specifically to fill
Dispatch's own idle time with real opportunity-hunting. Market Signal
Agent watches for genuine demand shifts (a new niche, a new platform, a
new client vertical) worth acting on. Idea Validation Agent
pressure-tests a new idea for real feasibility — cost, time, whether
the studio already has the skills built — before it ever reaches the
team, so half-baked ideas don't waste anyone's time. Cross-Pollination
Agent looks specifically for opportunities that combine both existing
divisions' skills (client-services' productization sense plus Edgex
Clips' audience-building sense, for example) — the kind neither
division would find working alone. Opportunity Logger writes every real
idea to the `opportunities` collection with actual backing, so nothing
dies quietly in one person's head.

## Venture Coordination (5 agents) — turns a validated idea into a real build

Once an idea clears validation, this department organizes the actual
cross-team effort. Venture Lead Agent plans who from which department,
in what order. Team Assembly Agent identifies exactly which existing
agents — from either division — are the right fit, and requests their
idle time through Task Dispatch rather than just pulling them off
whatever they're doing. Build Tracker Agent tracks the venture
end-to-end, the same way Command Center tracks a deal. Launch Readiness
Agent is the hinge back into the studio's real rules: anything the
venture produces that's client-facing or public gets routed to whichever
existing Last Touch actually applies — never skipped, never a new
shortcut. Venture Retro Agent checks honestly, after launch, whether the
thing is actually making money, and feeds that real answer back to
Opportunity Discovery so the next idea is better informed than the last.

## What this division does NOT do

- Never creates a new approval gate or a way around Last Touch, Video
  Last Touch, Chief of Staff, or the weekly budget process.
- Never assigns a task outside an agent's actual role just to look busy
  — a real, correct next task, or nothing.
- Never claims a venture is making money before Venture Retro Agent has
  actually checked.
- Never pulls an agent off client-facing or public-facing work mid-task
  without Team Assembly Agent coordinating a real handoff first.
